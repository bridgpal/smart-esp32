smart-esp32 · ESP32-S3 + Netlify

Press a button, ask a question, let go.

A $25 speaker board on a desk that answers out loud. The board only records and plays audio. A Netlify Function does the rest: it transcribes your question, asks Claude for a short answer, and streams the spoken reply back as it's generated.

One question, start to finish

Timings measured on the real board over Wi-Fi, counted from the moment you release the button.

  1. while held Board

    Listening

    Records 16 kHz audio from the mic array while you hold the talk button. The ring turns red.

  2. 0.0 s Board → Netlify

    Upload

    Posts the recording to /api/device/talk-stream. The ring turns blue.

  3. ≈ 2.0 s Netlify

    Transcribe

    OpenAI speech-to-text. The transcript streams back to the board's console first.

  4. ≈ 3.8 s Netlify

    Answer

    Claude, through the Netlify AI Gateway, writes one or two short sentences, streamed sentence by sentence.

  5. ≈ 5.0 s Netlify → Board

    Speak

    Each sentence becomes speech, is resampled to 16 kHz and plays while the rest is still arriving. The ring turns green.

Two halves, one repo

The board holds no API keys and no AI code. Swap models or prompts on Netlify without reflashing anything.

The board

firmware/ · C++, PlatformIO

  • ESP32-S3, 16 MB flash, 8 MB PSRAM, Wi-Fi
  • ES7210 dual-mic input, ES8311 codec and speaker amp
  • Seven-LED ring and three buttons: hold one to talk, press it again to interrupt a reply
  • Plays streamed audio after a 250 ms buffer

The Netlify site

site/ · TypeScript, Netlify Functions

  • Functions are the device's whole backend, routed at /api/device/*.
  • Streaming responses send reply audio out sentence by sentence instead of all at once.
  • AI Gateway supplies Claude credentials at runtime, so no Anthropic key is stored anywhere.
  • Environment variables hold the device token and the OpenAI speech key as secrets.
  • Git deploys from main, skipping the build when only firmware changes.

Device API

Every request needs the device token as Authorization: Bearer. Audio is raw PCM: 16 kHz, 16-bit, mono.

EndpointSendGet back
GET /api/device/pingnothingserver time, deploy ID, and which AI services are configured
POST /api/device/eventa button pressa color for the LED ring
POST /api/device/saytextthat text as speech
POST /api/device/talka recordingthe spoken reply, all at once
POST /api/device/talk-streama recordingtranscript, reply text and audio, streamed as frames

Requests without a valid token get 401. The board is the only intended client.
